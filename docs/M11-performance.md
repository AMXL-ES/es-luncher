# M11 · 性能与稳定（实测台账）

> 规矩：所有结论必须带数字与命令，形容词一律不算。每个数字都标注**怎么测的**与**限制**。
> 复跑：`scripts\bench-startup.ps1` / `scripts\bench-memory.ps1` / `scripts\bench-download.ps1`

## 1. 测试环境

| 项 | 值 |
|---|---|
| OS | Windows 11 25H2 build 26200，x64 |
| CPU / 内存 | 15.7 GB（同 `env-report.md`） |
| 构建 | Release，framework-dependent，.NET 10.0.401 |
| 数据根 | `D:\mc-data`（1.09 GiB，11 个实例目录） |
| 测试日期 | 2026-11-21 |

## 2. 冷启动（进程启动 → 主窗口句柄可交互）

`powershell -NoProfile -File scripts\bench-startup.ps1 -Runs 5 -JsonOut D:\mc-data\logs\bench-startup.json`

| 指标 | 数值 |
|---|---|
| 样本（ms） | 1334 / 1274 / 1313 / 1306 / 1284 |
| **中位数** | **1306 ms** |
| p95 | 1334 ms |
| 极差 | 60 ms（4.6%） |
| 中位常驻内存（工作集） | **124.6 MB** |

**对比 M0**：空窗口时 933 / 696 ms、99 MB；现在主页要读实例列表、加载图标与设置，所以慢了约 0.4 s、多了 25 MB。这个差值买的是「打开就能用」，不是退化。

**限制**：进程启动到 `MainWindowHandle` 非零不等于「画面完全画完」，是保守下界；含操作系统冷文件缓存影响，5 次里首次最慢（1334 ms）。

## 3. 常驻内存与挂机（`scripts\bench-memory.ps1`）

| 时间点 | 工作集 | 私有字节 |
|---|---|---|
| +0.05 min | 150.59 MB | 136.82 MB |
| +2.05 min | 181.02 MB | 160.98 MB |
| +4 ~ +17 min | 180.96 ~ 181.59 MB | 154.81 ~ 160.99 MB |

- **启动后 2 分钟内涨约 30 MB，随后 15 分钟基本不动**（漂移 < 1 MB）。这是字体/图标/纹理缓存的一次性开销，**不是泄漏**。
- 简单用「首尾差值 ÷ 时长」会算出 109 MB/h 的假象——分段看才看得出平台期。以后这类报告一律给曲线，不给单点斜率。
- 峰值 181.88 MB。

**意外**：这一轮进程在第 35 个采样点（约 17.1 min）**自行退出**。查证结果：Windows 应用事件日志无 `Application Error`/`.NET Runtime` 记录、WER 无报告 → **不是崩溃**，更像窗口被关掉或进程被外部结束。原因未查明，记为 `TODO(需复现)`，第二次 10 分钟复跑见 §6。

## 4. 下载吞吐（`scripts\bench-download.ps1`，全新数据根，SHA1 全程校验）

目标：MC 1.7.10 的 assets（674 个对象 / 107.4 MB），并发 8。

| 源 | 文件 | 体积 | 耗时 | 吞吐 | 失败 |
|---|---|---|---|---|---|
| **官方**（默认） | 676 | 107.4 MB | 66.4 s | **1.62 MB/s** | 0 |
| **BMCLAPI 镜像** | 673 | 104.8 MB | 527.4 s | **0.20 MB/s** | **5**（SSL 握手失败，重试后仍失败） |

**结论（与 M0 探活相反，照实写）**：单个小文件的镜像延迟确实更低（manifest 177 ms vs 1429 ms），但**批量资源下载时镜像慢 8 倍还带 5 个 TLS 失败**。所以默认源保持官方、镜像只做回退——这正是当前实现的策略，不需要改。

**限制**：单次测量、单一版本、本机网络；失败原因只记录了「SSL connection could not be established」，未做抓包定位（可能是镜像侧限流或本地连接数）。

## 5. 启动耗时归因与优化（2026-11-21）

埋点：`ESLUNCHER_STARTUP_TRACE=1` → `%TEMP%\esluncher-startup.log`（`StartupTrace`）。

优化前（同一台机器，冷启动 1306 ms 那一版）：

| 阶段 | 累计时间 |
|---|---|
| 进程启动 → Velopack 钩子 | 38 ms |
| → Avalonia 平台初始化完成 | 445 ms |
| 主窗口 ctor 开始 | 522 ms |
| **XAML 加载完成** | **1086 ms（这一段吃掉 ~600 ms）** |
| 资源与语言 | 1115 ms |
| 实例列表 + 主页渲染 | 1150 ms |
| 窗口显示 | 1283 ms |
| 第一次空闲调度 | 1448 ms |

**结论：慢在 XAML 加载，不在业务逻辑**。原因：下载页、设置页、关于页全都写在 `MainWindow.axaml` 里，启动时被整页实例化。

优化（三条）：

1. **重页面改懒加载**：`DownloadsView` / `SettingsView` 从内联元素改成 `ContentControl` 宿主 + 首次导航时创建；关于页整页抽成 `AboutView`，连 352 KB 的工作室图标一起按需加载。
2. **热路径不做 IO/解密**：顶栏账号名先用离线名填上，DPAPI 解密改后台异步。
3. **图片按目标尺寸解码**：`Bitmap.DecodeToWidth`（36px / 176px），不再整图解码。

优化后（同一台机器）：

| 指标 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| 冷启动中位数（5 次） | 1306 ms | **948 ms** | **−27%（−358 ms）** |
| p95 | 1334 ms | 976 ms | −358 ms |
| 常驻工作集（中位） | 124.6 MB | **112.1 MB** | **−12.5 MB** |
| XAML 加载 | ~600 ms | **~166 ms** | −72% |
| 第一次空闲调度 | 1448 ms | ~1032 ms | −416 ms |

首屏（主页）用户体验没有回退：仍然打开即显示实例名与启动按钮。代价是第一次进「下载 / 设置 / 关于」多 60–120 ms 的一次性构建，属于一次性成本。

## 6. 结论与待办

已达标的：

1. 冷启动 1.3 s、常驻 125 MB（空闲稳态约 182 MB）——对桌面启动器属于正常范围。
2. 挂机 15 分钟无漂移，没有观察到泄漏。
3. 下载吞吐有数字、失败可观测、SHA1 全程校验。

仍缺（M11 未完成的部分）：

1. **进程自行退出**要复现并定位（见 §3），必要时加未处理异常落盘与 `UnhandledException` 钩子。**（2026-11-21：用户要求暂停常驻内存测试，暂挂）**
2. **2 小时**级挂机（本轮只到 17 分钟）与「边下边玩」下的内存曲线。
3. 下载吞吐的多次采样取中位数（单次 1.62 MB/s 不能当 SLA 承诺）。
4. 大版本（26.x，587 MiB / 5,149 个对象）未测：会超 500 MB 授权线，需要单独批准。
5. UI 帧率/掉帧未测（Avalonia 无内置统计，需要加 Freeze 计数或 ETW）。
